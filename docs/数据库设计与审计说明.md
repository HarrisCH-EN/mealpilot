# 数据库设计与审计说明

更新时间：2026-09-18（Asia/Shanghai）

## 1. 权威来源与数据库

权威结构文件是 `database/01_schema.sql`，后续编号脚本用于迁移和回填。业务库为 `mealpilot`，集成测试库为 `mealpilot_test`；两者必须使用不同的连接配置。当前 Schema 共 19 张表：

```text
users, families, family_members,
ingredients, ingredient_seasons,
recipes, recipe_ingredients,
tag_definitions, recipe_tags_legacy, recipe_tags,
member_category_preferences, member_ingredient_restrictions,
recommendation_runs, recommendation_items,
recommendation_candidates, recommendation_candidate_items,
menus, menu_items, menu_feedback
```

## 2. 表的职责分组

| 分组 | 表 | 作用 |
| --- | --- | --- |
| 身份与家庭 | `users`, `families`, `family_members` | OpenID 用户、家庭、成员角色与邀请码 |
| 菜谱基础 | `recipes`, `ingredients`, `recipe_ingredients`, `ingredient_seasons` | 菜谱、食材、用量和季节 |
| 标签与偏好 | `tag_definitions`, `recipe_tags`, `recipe_tags_legacy`, `member_category_preferences` | 系统/家庭标签、菜谱标签和成员偏好 |
| 限制 | `member_ingredient_restrictions` | 成员级过敏、忌口和排除食材 |
| 推荐 | `recommendation_runs`, `recommendation_candidates`, `recommendation_candidate_items`, `recommendation_items` | 当前候选模型与旧兼容路径 |
| 菜单与反馈 | `menus`, `menu_items`, `menu_feedback` | 日期餐次菜单、菜品和反馈 |

## 3. 约束与索引原则

- 家庭邀请码使用大小写敏感的 ASCII 唯一约束；同一家庭与用户的成员关系唯一。
- 菜谱状态限制为 active/deleted 等受控值；软删除不破坏历史菜单项。
- 标签定义约束系统标签与家庭自定义标签的作用域；菜谱标签通过复合唯一键去重。
- 推荐候选 rank 约束在 1 到 3；候选项按候选和菜谱唯一。
- 菜单按家庭、日期、餐次唯一；菜单项按菜单和菜谱唯一；反馈按菜单项和成员唯一。
- 外键均指向所属家庭或父级记录，删除策略以保留历史可审计性为优先。

## 4. 家庭数据边界

所有家庭业务 SQL 都必须从 JWT 当前用户出发，确认 `family_members` 成员关系，再把 `family_id` 作为查询、更新和删除条件。不能仅凭客户端传入的家庭 ID 授权。推荐读取家庭成员偏好、家庭忌口、家庭菜谱和菜单时也遵循同一边界。

## 5. 推荐结构的当前与兼容路径

当前推荐写入链为：

```text
recommendation_runs
  └─ recommendation_candidates
       └─ recommendation_candidate_items
```

`recommendation_items` 是旧接口兼容路径，保留用于历史数据和无候选 ID 的旧应用请求。新客户端应提交 `candidateId`；服务端在事务中重新校验候选状态、家庭、成员、菜谱、忌口和菜单结构。

## 6. 迁移与初始化

新环境先执行 `00_create_user.sql`（需要管理员权限），再由服务端脚本初始化 `01_schema.sql`，之后按编号执行 `04` 至 `10` 的迁移脚本并根据需要运行 seed。迁移脚本不是任意可重复的 SQL；执行前记录目标库、脚本版本和备份点。

## 7. 审计范围

本次重构核对了 Schema、服务层家庭边界、推荐写入和测试配置，没有连接生产库执行写操作，也没有把未运行的实时数据库审计描述为已通过。需要上线前继续验证：外键孤儿、跨家庭关系、重复 active 成员、上传 File ID 存在性和迁移后索引。

系统菜谱的早期 seed 占位媒体值只用于初始化兼容；家庭初始化和媒体迁移脚本会根据系统封面映射写入稳定 CloudBase File ID。运行时新建或编辑菜谱不得把临时展示 URL 当作持久字段。

## 8. 安全要求

数据库密码、JWT 密钥、微信 AppSecret 和 CloudBase 服务端凭据只允许出现在运行环境变量或本机 `.env`。SQL 日志、测试快照、课程报告和接口响应不得打印这些值。测试库写入必须显式开启，避免误写业务库。
