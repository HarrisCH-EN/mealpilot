# 系统架构与部署说明

更新时间：2026-09-18（Asia/Shanghai）

## 1. 总体链路

```text
微信客户端
  └─ 原生小程序页面（WXML / WXSS / JavaScript）
       └─ utils/api.js → http-client.js：callContainer + Bearer JWT
            └─ CloudBase 云托管 mealpilot-api
                 └─ Node.js + Express
                      ├─ JWT 与家庭成员中间件
                      ├─ Auth / Family / Recipe / Tag / Menu / Recommendation
                      │  Restriction / Preference / Feedback / Upload 路由
                      ├─ 业务服务与事务
                      ├─ MySQL 8：mealpilot
                      └─ CloudBase 私有 Storage
```

微信登录另外调用微信开放能力 `code2Session`，服务端只把 OpenID 映射到用户并签发 JWT；`session_key` 不保存、不返回。

## 2. 前端运行时

`project.config.json` 的 `miniprogramRoot` 是 `miniprogram/`。生产小程序由 `miniprogram/config.js` 配置 cloud transport，通过 `wx.cloud.callContainer` 访问环境 `cloud1-d1gvr0mwv39a12cbd` 中的 `mealpilot-api`，接口路径以 `/api` 开头。旧公网地址仅保留给历史 `/uploads/...` URL 的展示兼容。

`utils/api.js` 保持页面接口，`utils/http-client.js` 注入 Bearer Token、处理 401 和错误响应，并按环境选择传输方式。页面只通过请求封装访问后端，不自行拼接部署域名。

## 3. CloudBase 云托管

生产后端服务名为 `mealpilot-api`，运行 Node.js + Express 应用。`/api` 是 Express API 路由前缀；开发环境继续使用 localhost HTTP 请求与 multipart 上传。部署时必须通过环境变量注入数据库、JWT、微信和 CloudBase 凭据，凭据不进入小程序包、接口响应、日志或文档正文。

## 4. 数据访问

服务端使用 `mysql2/promise` 连接池。涉及推荐应用、菜单写入和家庭状态变化的操作使用事务，并在 SQL 中重复校验 `family_id` 与成员关系。数据库结构以 `database/01_schema.sql` 和编号迁移脚本为准；初始化和迁移顺序见[数据库设计与审计说明](数据库设计与审计说明.md)。

## 5. 媒体存储

CloudBase Storage 使用私有权限。服务端上传成功后返回稳定 File ID，并在需要展示时生成临时 HTTPS URL：

```text
资源源文件 resources/recipe-images/
        └─ 部署路径 system/recipes/
             └─ 数据库 cover_file_id（cloud://...）
                  └─ API 响应 coverUrl（临时 HTTPS）
```

用户封面和头像分别通过上传路由处理。系统菜谱封面由代码映射表维护，不依赖本地开发机路径。前端展示时优先使用短期 URL；更新或删除时使用稳定 File ID。

## 6. 认证与家庭边界

```text
wx.login
  → /auth/wechat-login
  → code2Session
  → users.openid
  → JWT
  → auth middleware
  → family_members
  → family-scoped SQL
```

家庭是逻辑多租户单位。Owner、Admin、Member 角色由 `family_members.role` 表示；读写权限在路由和服务层共同执行。邀请码为 6 位 ASCII 数字与大小写字母组合，刷新后旧值立即失效。

## 7. 生产配置边界

服务端需要的配置包括端口、MySQL 连接、JWT 签名密钥、微信 AppID/AppSecret、CloudBase 环境和 Storage 前缀。生产环境应设置 `NODE_ENV=production`、关闭开发登录，并使用独立的最小权限数据库账号。真实 `.env` 不应提交到 Git。

## 8. 运维与回滚要点

1. 发布前先运行后端直接测试和小程序测试。
2. 数据库变更按编号脚本执行，保留迁移日志。
3. CloudBase 服务发布后检查健康接口、微信登录、家庭边界、上传和临时 URL。
4. 回滚应用版本时不要回滚已经成功执行的不可逆数据迁移；先确认兼容性。
