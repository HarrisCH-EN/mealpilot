# 项目现状说明

更新时间：2026-09-24（Asia/Shanghai）

## 1. 项目定位

MealPilot / 饭有谱是面向家庭场景的微信小程序。用户通过家庭数据边界管理菜谱、菜单、成员偏好和忌口，并获得可解释的规则推荐。推荐系统是确定性规则与加权评分，不是机器学习、协同过滤或大模型服务。

## 2. 当前技术栈

- 前端：原生微信小程序，`miniprogram/` 下的 WXML、WXSS 和 JavaScript。
- 后端：Node.js + Express，使用 `mysql2/promise`、JWT 和 dotenv。
- 数据库：MySQL 8.0+，数据库名 `mealpilot`；独立测试库为 `mealpilot_test`。
- 云部署：CloudBase 云托管服务 `mealpilot-api`。
- 对象存储：CloudBase 私有 Storage；数据库保存稳定的 `cloud://` File ID，前端使用临时 HTTPS URL 展示。
- 测试：Node.js 内置测试运行器；后端测试位于 `server/test/`，小程序测试位于 `tests/miniprogram/`。

## 3. 运行与部署现状

生产小程序通过 `miniprogram/config.js` 指定 cloud transport，由 `wx.cloud.callContainer` 访问环境 `cloud1-d1gvr0mwv39a12cbd` 中的 `mealpilot-api`。开发环境保留 localhost HTTP；旧公网地址仅用于历史 `/uploads/...` URL 的展示兼容。小程序工程配置 `project.config.json` 将 `miniprogram/` 设置为小程序根目录。CloudBase 云托管服务接收 HTTPS 请求，Express 应用负责认证、业务路由、事务和数据访问。

## 4. 已实现能力

- 微信登录、JWT 会话、当前用户资料和全局登录闸门。
- 家庭创建、邀请码加入、家庭改名、成员角色和成员移除。
- 菜谱列表、详情、新增、编辑、软删除、食材、步骤和封面。
- 按日期与餐次管理菜单，支持手动加菜、备注、删除和幂等添加。
- 成员级类别偏好与忌口；忌口用于推荐硬过滤。
- 规则推荐、候选集、解释文本、候选替换和应用到菜单。
- 菜单项评分与文字反馈，以及 7/30 天基础洞察。
- 系统菜谱素材从 `resources/recipe-images/` 维护，部署到 Storage 的 `system/recipes/` 路径；运行时通过 `server/src/data/system-recipe-covers.js` 映射。

## 5. 当前数据与媒体事实

- `database/01_schema.sql` 定义 19 张业务表；正式结构和约束见[数据库设计与审计说明](数据库设计与审计说明.md)。
- 系统封面映射当前有 47 条，源资源目录有 47 个文件。未映射的种子菜谱是“红豆小米粥”，前端需要保留无封面 fallback。
- 生产图片上传经 Backend prepare → `wx.cloud.uploadFile` 写入 staging → Backend commit 下载校验和转存；开发环境保留 multipart。用户上传的菜谱封面和头像进入 CloudBase 私有 Storage。响应同时区分稳定的 `coverFileId` 与短期展示用 `coverUrl`，前端不得把临时 URL 当作持久标识。
- 家庭采用逻辑多租户：`family_id`、JWT 用户身份、`family_members` 成员关系和所有家庭范围 SQL 共同构成隔离边界；没有按家庭拆分物理数据库。

## 7. 当前限制与后续工作

- 生产发布仍需要在微信开发者工具和真机上确认登录、上传及临时 URL 展示；当前 Storage 规则是“仅创建者及管理员可读写”，正式发布前仍需验证客户端仅能写 `staging/`，不得在正式资源路径创建文件。
- Storage 文件生命周期清理、病毒扫描、CDN 和大文件策略不在当前业务代码范围内。
- 推荐模型仍是可解释规则，尚未引入用户级长期学习或离线评估流水线。
- 图表 PNG 保留现有导出版本；本机没有可用的 draw.io CLI，本轮只同步可编辑源文件，PNG 需要在 draw.io 中手动重新导出。
