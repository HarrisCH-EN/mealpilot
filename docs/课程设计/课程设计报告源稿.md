# 基于微信小程序的家庭膳食管理与菜谱推荐系统

## 课程设计报告源稿（当前实现版）

更新时间：2026-09-18（Asia/Shanghai）

> 本源稿服务于课程设计写作和排版。当前实现事实以仓库代码、`database/01_schema.sql` 和 `docs/` 正式说明为准；排版交付物见同目录 DOCX。

## 摘要

MealPilot / 饭有谱面向家庭用户提供菜谱、菜单和规则推荐。系统采用原生微信小程序、Node.js + Express、MySQL 与 CloudBase 云托管。家庭通过成员关系形成逻辑多租户边界；推荐先执行忌口硬过滤，再按偏好、食材与烹饪方式多样性、营养、季节和新颖度排序，并把候选集持久化以支持可解释的换一组和幂等应用。

## 1. 需求与总体架构

用户完成微信登录后进入家庭工作区，可以维护菜谱、菜单、标签、偏好和忌口。小程序请求生产 API，API 部署在 CloudBase 云托管 `mealpilot-api`，业务数据在 MySQL `mealpilot`，图片在 CloudBase 私有 Storage。登录由微信 `code2Session` 建立 OpenID 映射并签发 JWT。

```text
小程序 → HTTPS /api → CloudBase 云托管 mealpilot-api
       → Express 认证与业务服务 → MySQL mealpilot
                                  └→ CloudBase 私有 Storage
```

## 2. 前端实现

小程序根目录是 `miniprogram/`，页面覆盖登录、推荐、菜单、菜谱、设置、家庭、账号、标签和忌口。`utils/api.js` 统一处理 API 基地址、Bearer Token、401 和错误；`app.js` 负责会话与全局登录闸门。生产地址由 `miniprogram/config.js` 提供。

## 3. 数据库设计

`database/01_schema.sql` 当前定义 19 张表，分为身份家庭、菜谱食材、标签偏好、限制、推荐和菜单反馈六组。所有家庭 SQL 都同时使用 `family_id` 和 `family_members` 成员校验；推荐当前链路为 `recommendation_runs → recommendation_candidates → recommendation_candidate_items`，`recommendation_items` 保留兼容历史接口。

## 4. 推荐方法

推荐输入包含日期、餐次、标签偏好、准备时间、数量和结构。系统过滤成员忌口、已删除菜谱和不完整结构，再以 preference 30、ingredientDiversity 15、methodDiversity 10、nutrition 15、seasonal 10、novelty 20 的权重排序，最多保存 3 个候选。应用时客户端提交 `candidateId`，服务端在事务中重新验证家庭、成员、菜谱状态、限制和结构并幂等写入菜单。

## 5. 媒体与素材

系统菜谱图片源文件位于 `resources/recipe-images/`，部署到 Storage 的 `system/recipes/`。数据库保留稳定 `cloud://` File ID，接口返回短期 `coverUrl` 供展示。上传素材的作者、来源、许可和 `REFERENCE_ONLY` 标记见[菜谱图片素材来源说明](../菜谱图片素材来源说明.md)。

## 6. 界面设计

界面使用 `#ff385c` 主色、白色画布、灰阶文字、卡片和胶囊控件。页面、表单、弹层、加载、空状态和错误状态使用 `app.wxss` 中的统一变量；按钮与输入控件保持足够触控尺寸。完整令牌见[界面设计规范](../界面设计规范.md)。

## 8. 结论与展望

当前版本已经形成从微信登录、家庭边界、菜谱和菜单管理到规则推荐、候选应用、图片存储和反馈洞察的闭环。后续工作包括真机发布验收、Storage 生命周期治理、推荐离线评估和更细的权限审计。本文不把未实现的机器学习推荐、实时通知或物理多租户描述为现有功能。
